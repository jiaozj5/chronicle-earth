# 岁月史书

一个保存在本机的个人史书与知识工作空间。你决定记录什么、如何理解它，以及哪些内容仍只是预言或问题。

最初的想象是“云下的真实地球与岁月史书，云上的思想与人物”。当前实现把它落为可以记录、阅读、引用、讨论和回顾的本机应用。完整愿景不等于当前交付范围。

## 打开应用

首次获取：

```text
git clone https://github.com/jiaozj5/chronicle-earth.git
cd chronicle-earth
```

Windows 双击 **`start.cmd`**。它会启动本机服务并打开 **http://127.0.0.1:4317**。再次打开会复用已运行的服务。

本机需要 Node.js 24 或更新版本。新电脑请自行准备 Node；也可以在本目录运行：

```text
node apps/server/main.js
```

无需安装前端依赖。地理数据、Markdown、公式字体与渲染资源都随应用提供。外网断开时，只要本机服务仍在运行，核心记录、阅读、搜索和整理可以继续。

首次启动自动创建空白个人工作空间。PDF/图片等转换需要额外的 Python 依赖，见[转换环境](docs/07-library-implementation.md)；开发测试依赖见[维护手册](docs/12-maintainer-guide.md)。服务不会自动随电脑开机运行，访问失败时先运行启动器。

## 从第一笔开始

1. 点击右上角「记一笔」，写一句话就能保存。标题、时间、地点和来源都可以稍后补充。输入后的保存状态会说明草稿是否已落盘。
2. 地图以城市入口汇总记录；也可以保存自定义地点。选择地点和时间仅改变观看与新记录的上下文，写作中的归属不会被悄悄替换。已收录且归属明确的记录才会点亮地图。
3. 「思想体系」里可以独立建立文稿、概念、观点、问题或论证，使用 Markdown、表格、公式与可追溯引用；不用先绑定时间地点。
4. 进入「材料藏书」内的「格式转换」，上传 PDF、扫描件、EPUB、Markdown 或文字，检查并下载转换结果；决定收录后再点击「加入藏书」。在藏书中进入原版或重排阅读，选中文字、公式和原页区域后标记批注。「原材料与摘录」保留原有编辑入口。扫描识别结果明确标为待校对，未解析附件不会被当成已读全文。
5. 「云上人物」可塑造名字、形象、风格并选择资料。在「工作空间设置」连接模型后再开始真实讨论；没有配置时不会生成示意回答。每场讨论固定资料版本，采纳前可修改正文并选择目标。
6. 预言有独立身份。以后可以修订和复盘，首次版本及评估依据仍能回看。

史书页以地图为主体，地名用浅色文字显示。点击地图地点或「记录目录」展开侧栏，点一条记录阅读；「记一笔」直接进入书写。「收起」保留当前正文与草稿，「专注阅读」扩大阅读区域。刷新会保留当前面板开合状态。

顶部搜索查找整个工作空间；页面内搜索用于当前目录。`Ctrl/Cmd + K` 定位搜索；`Alt + ←` 返回上一个工作位置。正文支持显式保存与可恢复草稿，发生版本冲突时会保留未提交内容。

在地图工具栏展开「图层与地点管理」→「管理自定义地点」，可删除自己创建的地点；勾选「显示已删除地点」即可恢复。删除地点不会改写原记录、历史地名或引用，恢复后重新显示关联的探索。

## 让模型操作史书

工作空间设置 →「让模型操作史书」→「复制 MCP 连接配置」，将配置交给支持本机 stdio MCP 的模型客户端。应用服务保持运行，模型就能通过明确的工具查询地点、解析日期、写入和修订记录、创建及删除恢复自定义地点。

9 项操作也提供本机 HTTP 接口与 JSON Schema。同名地点返回候选；写入使用唯一请求标识，重试不会重复记录；修改需提供读取过的版本。模型写入的内容会自动同步到地图和目录，不替换正在书写的草稿。接入步骤、参数和可运行调用示例见 [模型操作接口](docs/06-agent-operations.md)。真实自然语言理解效果需接入你选定的模型后验证。

## 数据与备份

材料藏书支持高亮、下划线、方框、三角形、实心点、空心圈、大圆圈、叉号、对号与斜杠。书目菜单可导出完整 `.book.zip` 阅读包或 JSON-LD 批注；书架上的「Agent 接口」提供 MCP 配置。PDF 与扫描件默认打开原版，结构化文字供重排、搜索和校对。公式的原始外观以原页为准；本机基础 OCR 不生成可靠 LaTeX。使用方法、转换环境和验证边界见 [材料藏书实现与使用](docs/07-library-implementation.md)。

阅读页左侧只保留目录与查找，聊天和模型选择在外部 Agent 中完成。Codex 等本机 MCP 客户端可以读取当前选区、翻页、写改批注和校对原文；接入配置及操作规范见 [外部 Agent 接入](integrations/chronicle-library/README.md)。普通豆包网页/桌面客户端的自定义工具入口尚未核实，不宣称已经接通。

- 内容数据库、全部修订和附件位于 `.local/workspaces/`；当前空间由 `.local/active.json` 指向。
- 设置中的「导出完整备份」生成 `.chronicle` 文件，包含正文、草稿、引用、讨论、采纳链与附件，显示实际处理进度。
- 恢复先校验到新的工作空间，成功后才切换；原空间保留。损坏或不兼容的备份不会覆盖现有内容。
- 模型地址、模型名和密钥在 `.local/settings.json`；密钥不会返回界面，也不会进入史书备份。完整应用目录属于你的本机文件。
- `start.cmd` 的运行日志在 `.local/server.log` 与 `.local/server-error.log`。开发测试使用独立临时数据，不向你的史书加入测试记录。

## 验证与当前交付状态

这是可运行的工程候选版本。真实模型讨论质量将在你连接服务后验证；真实用户任务和一周复访仍需实际参与者，自动化检查不代替这些结论。

```text
node scripts/check.mjs
node --test
node scripts/acceptance.mjs
node tests/performance/run.mjs
```

验收入口依次执行核心数据流程、云上界面、从地图出发的完整链路、应用壳检查，以及真实 MCP 进程调用和地图侧栏流程。浏览器验收使用 Playwright / Edge，属于开发测试依赖，普通运行不需要。性能命令会生成较大的合成数据与备份，运行条件和结果写入 `quality/`；已有完整测试库时，`node tests/performance/recheck.mjs` 可复测查询、地图与草稿反馈，`node tests/performance/ui-feedback.mjs` 补测真实界面反馈。

功能边界、模块责任与验收标准见 [工程文档](docs/README.md)，本次结果见 [应用交付记录](docs/05-delivery.md) 和 [55 项验收矩阵](quality/验收结果.md)；各模块 `HANDOFF.md` 记录局部实现及验证。规格中的数值是门槛，只有实测报告明确列出的项目才能视作已验证。

上述应用交付记录和验收矩阵保留首版历史。2026-10-03 源码交接重新执行了 156 项测试和 90 个模块检查；本次未重跑全量浏览器、性能或真实模型质量评估。以[当前状态](docs/11-status-and-roadmap.md)和[验证摘要](quality/handoff-validation.json)为接手基线。
