# 共享领域与接口契约

版本：v0.1。唯一维护者：A0。本文冻结领域含义和模块边界，不预设 HTTP、数据库或具体编程语言。G0 将本文转成机器可检查的结构、接口签名和契约测试，后续智能体不得各自发明平行类型。

## 内容对象与所有权

所有正式对象具有稳定 `id`、`objectType`、`revision`、`createdAt`、`updatedAt`、`deletedAt`。ID 不由名称、坐标或正文生成；创建后不变。系统时间使用 UTC 时间戳；界面按工作空间时区显示，不改变内容发生时间。

| 对象 | 业务规则负责人 | 含义及必要信息 |
|---|---|---|
| Draft 草稿 | A2 | 尚未提交的正文、编辑目标、待确认时空标签、最后持久化状态 |
| Entry 记录 | A2 | 用户正文、可选标题、kind、occurrenceTime、placeRefs、收录状态、来源与引用 |
| PredictionReview 预言评估 | A2 | 预言稳定 ID 与明确版本、评价、用户依据、评估创建时间 |
| Place 地点 | A3 | 类型、名称及有时间范围的别名、可选锚点与范围、上级关系、旧 ID 重定向 |
| TimeView 时间视图 | A3 | 名称、查询范围、显示偏好；不持有记录列表的权威副本 |
| KnowledgeItem 知识项 | A4 | concept、claim、question、argument；独立正文及可选结构化前提/结论 |
| Document 文稿 | A4 | 自有段落、稳定段落 ID、有序章节及对已有对象的引用块 |
| Source 来源 | A4 | 书目或来源描述、原始材料、解析状态、修订与定位信息 |
| Citation 引用 | A4 | 被引对象身份、版本策略、片段定位、引用文本及来历 |
| Relation 关系 | A4 | 起点、终点、类型、可选解释、出处；不自动等同因果 |
| Persona 人物 | A5 | 自定义形象与风格、关联来源集合、用户诠释、实际资料覆盖 |
| Discussion 讨论 | A5 | 上下文对象及版本、人物及资料集合快照、稳定身份的消息、运行状态、采纳回执 |
| Message 讨论消息 | A5 | 全局稳定 messageId、discussionId、独立修订、角色、正文、引用、生成状态 |

A1 负责以上对象的通用持久化、版本、索引及备份机制。业务负责人决定合法内容与业务变化，A1 不自行改写领域含义。类型声明与通用数据封装由 A0 维护；业务模块提交已通过自身校验的命令到 A1。

不另建必须去重的全局历史事件真相库。用户可以为同一事件留下多条不同观察；是否归为同一事件，由用户主动建立关联或文稿组织。

## 草稿与正式记录

- 任意非空正文都可提交；标题、来源、地点和时间均不强制。只有附件或有效引用、尚无文字的内容也可先存草稿。
- `Draft` 自动保存不等于正式收录。草稿通过待整理入口可找回，不参与正式记录数量、普通搜索结果及地图探索；搜索可显式选择包含草稿。
- 正式 Entry 的收录状态为 `inbox` 或 `adopted`。批量导入默认 `inbox`；用户主动记录默认 `adopted`。
- `inbox` 是可检索的待整理内容，但不点亮地图。缺失时间地点的 `adopted` 记录仍已保存，进入待定位视图，补齐信息后沿用同一 ID。
- 提交前可见的时间地点标签就是此次落点的确认。不得为已可见上下文增加第二次确认。自动识别的候选未被接受前不得充当已确认归属。
- 起草时固定本草稿上下文。之后切换地图地点不暗中改变已输入草稿的归属；可以主动更换标签，或者另起一笔。
- 持久化中的草稿与已确认保存的正式记录需分别表达。提交成功并持久化后，才能清除该草稿；提交失败保留正文和重试入口。

## 时间语义

`createdAt` 表示首次写下时间，`occurrenceTime` 表示内容所指时间，二者独立。预言的目标时期属于 occurrenceTime；评估日期属于评估对象。

TimeSpec 的共同字段：`originalText`、`calendar`、`kind`、`precision`、`approximate`、`earliest`、`latest`。kind 至少区分 `instant`、`duration`、`uncertain`、`unknown`。日期精度为年、月、日；开放边界为 null，不采用特殊字符串。

- “1850—1860 年持续发生”是 duration；“在 1850—1860 年之间发生，但具体日期不明”是 uncertain。查询可能相交，但展示不能混淆两者。
- 索引采用前推公历，显示纪年采用 `era=CE|BCE` 与正整数年，界面没有公元 0 年。内部若使用天文年，公元前 n 年对应 1−n；转换由同一时间库完成。
- V1 可索引范围为公元前 10000 年至公元 10000 年；范围之外保留原文并进入未索引时间，不截断、不丢弃。
- 边界日期对用户按包含端点解释；机器查询统一成半开日区间 `[startDay, endDayExclusive)`。年/月精度扩展为该年/月全范围，不能强行显示为 1 月 1 日发生。
- 查询相交规则：`entry.start < view.end && view.start < entry.end`。多个选中视图结果取 ID 并集。
- 单侧开放边界在查询比较中按负无穷或正无穷处理，但只展示可索引纪年范围内的部分。两侧均未知属于 unknown，不参与时期探索。超出索引范围的原始日期不得偷换成开放边界。
- G0 固定三个不同夹具：“1850 年以后”严格按该年结束以后，即 1851 年起且终点开放；“1850 年以前”严格按该年开始以前，即最晚 1849 年结束；“时间不详”无边界。输入界面展示解释后的范围；“从 1850 年起”“截至 1850 年”则包含该年，不共用同一字符串解析结果。
- uncertain 的查询边界代表可能发生范围，匹配时注明时间不确定。只有原文、没有足够边界时，归入未知时间，不擅自把“前后”解释为固定若干年。
- 时间视图的拆分、合并、重命名、重叠选择不能复制、删除或改写记录。时间未知的记录通过待定位或“含未知时间”选项找到，不在具体时期生成探索覆盖。

## 地点、计数与探索

Place 的类型至少支持 city、settlement、region、naturalFeature、route、custom。几何可为点、线或范围；位置尚不明确时可保留文字，无强制精确坐标。

地点别名只是候选匹配线索。同名不等于同一地点，城市迁址不自动合并。用户可以保留历史名称；重复地点合并要保留旧 ID 的跳转，不由地图渲染触发。

Entry 可以关联多个 PlaceRef，包含地点 ID、可选角色和此处的原始名称。对同一个 placeId 的重复关联不重复计数。

统一计数：

1. 地点数量 = 满足时间条件、非删除、adopted 的唯一 Entry ID 数；显示名为“记录数”，不称“事件数”。
2. 地图区域或地图全域汇总 = 各地点关联记录的 ID 并集大小；不能把城市计数直接求和。整个史书的记录总数还包含无地点记录，应由 Entry 查询单独统计，不能复用地图汇总。
3. 筛选后数量与总探索状态分开命名。用户筛掉所有当前结果时，已探索状态仍可存在。
4. 地图聚合只改变展示，不修改记录、地点归属、查询结果或探索事实。

探索资格 = adopted 且未软删除的 Entry，至少一个已确认且可定位的 PlaceRef，且有可索引的 occurrenceTime。普通记录与预言都可构成探索。

- 浏览、搜索、读取人物资料、自动导入待整理内容和未采纳的聊天都不产生探索。
- 修改时间或地点后，重新计算旧与新归属；删除最后一条合格记录后恢复迷雾；恢复记录后重新点亮。
- 临时过滤、隐藏图层内类别或折叠目录不改变探索资格。首版没有独立“永久足迹”对象，避免删除语义分裂。
- 宏观地区或路线记录只表达对应尺度的关注，不能使内部每座城市都成为已探索。
- 迷雾的视觉半径由 A3 决定，但不能表达比记录归属更精确的史实或更广泛的已探索范围。

## 引用、修订与删除

CitationRef 共同字段为 `targetId`、`versionMode=live|pinned`、`revision`、`locator`、`quote`。pinned 必须指定 revision。locator 可使用文稿段落 ID、原文范围、页码或附件位置；范围校验失败需显示无法定位，不能静默跳到错误内容。

- 地点目录和一般导航默认 live，指向当前对象。
- 作为论证证据、预言依据、人物原文引述时默认 pinned。引用时固定采用的版本，避免证据随编辑无声变化。
- 原对象出现新版本时，保留旧证据并提示可检查新版本；用户主动更新引用。体系自有正文不自动被改写。
- 跟随当前对象的多个入口展示同一个身份。用户主动“另存为副本”才产生新 ID，并保留派生来源；该功能不列为首版必需。
- 关系方向遵守下表。自引用和关系环不默认等同错误，但不能造成无限遍历；地图坐标和时间先后不自动生成逻辑关系。
- 软删除保留 ID、版本和附件引用；默认目录搜索隐藏，被引用处显示已删除并允许恢复。禁止级联删除依赖它的观点、章节或讨论。
- 恢复使用原 ID，索引与地图状态恢复。首版不提供逐对象永久清除，也不在迁移时静默丢弃旧版本。

| 关系 | 起点 → 终点 | 反向名称 |
|---|---|---|
| supports | 材料或论证 → 被支持的观点、论证或预言 | 受到支持 |
| refutes | 材料或论证 → 被质疑的观点、论证或预言 | 受到质疑 |
| defines | 定义文字 → 被定义的概念 | 定义来自 |
| premiseOf | 前提命题或记录中的判断 → 论证 | 前提包含 |
| exampleOf | 实例 → 概念或观点 | 例子包含 |
| relatedTo | 任意两个正式内容对象，对称关系 | 相关 |

材料可引用 Source、Entry、KnowledgeItem、Document 或已定稿讨论消息及其片段。定义文字可来自上述对象的明确片段；论证终点必须为 argument 知识项，概念终点必须为 concept。relatedTo 端点限 Entry、Source、KnowledgeItem、Document、Persona 和已定稿讨论消息，不包含草稿或纯界面状态。对称关系以规范化端点顺序去重。所有端点使用统一 CitationRef，不能用数组序号或正文字符串代替身份。

## 预言与人物

Entry 的 `kind=note|prediction` 是用户选定的身份，不能依据现实日期自动改写。首次以 prediction 提交时保存 `initialPredictionRevision`；后续修改产生新版本。

PredictionReview 指定被评估的预言版本，状态至少支持 pending、supported、partlySupported、notSupported、indeterminate。评估是用户判断，可修订；系统不宣称其为客观判定。多个未来情景首版使用多条预言加显式相关关系和条件表示，不引入第二套分支版本系统。

Source 原始材料与 Persona 风格、用户对人物的诠释分开。资料清单显示已导入、可检索、未解析的状态。某人物的实际检索范围必须明确；尚未收录的知识不得以“全集已知”呈现。

Discussion 至少分辨用户消息、原文引用、解释与本次推演。只有经资料匹配的片段可标为原文引用；解释与推演不能伪装成人物历史原话。

模型调用只能获得本次讨论明确选中的上下文与人物资料范围，不默认包含整个私有工作空间。外部推理服务的配置与可见资料范围在首次使用时清楚展示。

资料范围由 A5 根据人物配置与本次选择构造为明确的 `SourceRef[] = {sourceId, revision}[]` 快照，A1 严格检索这些版本并返回相同版本与稳定定位，A4 是对象/版本/片段/原文及允许范围校验的唯一实现者，A5 负责调用与展示结果。讨论期间来源更新不能偷偷替换已冻结版本；使用新资料需生成新的上下文快照。无结果不能自动扩大检索范围。本次用户提供的上下文单列并可参与讨论，但不因此变成人物的历史留存。

每条讨论消息有全局稳定 messageId 和独立 revision，引用定位为 `{discussionId, messageId, revision}`。映射到通用 CitationRef 时，targetId 为 messageId，revision 为消息修订，locator 保留 discussionId 和片段；不把讨论容器的版本误当消息版本。追加消息不改变既有引用；重新生成使用新的 messageId，编辑已完成消息产生新 revision。流式未定稿文本不能被标记为可引用的最终原文；取消后保留中断身份。

未被采纳的消息不进入史书、知识对象统计或地图探索。用户执行采纳时，A2 对 Entry/PredictionReview、A4 对知识项/文稿与引用、A5 对讨论采纳回执分别提供经过业务校验的待提交变更。A0 组合成单一变更集，A1 一次原子提交并返回回执。A0 只编排，不代替业务校验；准备变更的过程不先写入正式对象。讨论不能在目标尚未保存时标记采纳成功。

采纳回执包含 commitId、消息引用、受影响对象 ID 及修改前后版本。撤销也由各对象负责人准备补偿变更，经 A0 编排、A1 校验期望版本并原子提交，保留原讨论和历史。若采纳后对象已经产生其他修改，不允许整段回滚覆盖后续内容，返回冲突并保留两边内容，提供人工合并或放弃撤销的路径。创建型采纳的撤销使用软删除；修改型采纳的撤销产生一个新的恢复版本。新对象已被其他内容引用时，撤销前明确显示影响；已有引用保留为可恢复的删除提示，不能级联丢弃。重试依然幂等。

讨论失败、取消或没有可用模型时，已存资料和核心记录编辑仍可用。首版发布验收必须完成至少一次真实端到端资料型讨论；仅凭模拟回答不能声称 F08 已交付。模型暂不可用时，其余工程可继续，但 F08 状态须明确未验收。

## 公共能力与接口责任

|---|---|---|
| A1 Workspace | commit、get、history、softDelete、restore、search、searchSourceVersions、export、import | 原子变更集、期望版本、幂等键；返回提交版本与保存回执；查询带索引水位；资料检索限制 sourceId 与 revision |
| A2 Chronicle | startDraft、saveDraft、submitEntry、reviseEntry、reviewPrediction、openEntry、prepareAdoption、prepareAdoptionUndo | 草稿上下文、正文、时空确认、kind；业务结果或待提交变更及期望版本 |

| A4 Knowledge | createItem、editDocument、createSource、attachCitation、validateCitation、relate、incomingRefs、prepareAdoption、prepareAdoptionUndo | 引用语义、目标版本、片段、关系方向与允许资料范围；提供知识及引用待提交变更 |

## 写入、事件与错误

- 更新带 expectedRevision；不匹配返回 VERSION_CONFLICT 及当前版本，不静默覆盖。
- 创建、提交、导入、采纳、删除和恢复均带 requestId。同一请求及同一内容重试，返回同一结果；相同 requestId 配不同内容返回 IDEMPOTENCY_CONFLICT。
- 相互依赖的变更必须原子提交，例如采纳生成知识项及其来源关系、提交正式记录及处理对应草稿。部分失败不能留下被误认为完整的对象。
- 只有权威存储确认后返回已保存。草稿暂存、正式提交、索引更新、备份完成分别反馈。
- 提交发布 ObjectCommitted 或 ObjectDeleted/Restored，携带 objectId、objectType、revision、commitId、workspaceSequence。A3 投影与 A1 索引消费已提交变化；不得只监听当前页面操作。
- 地图与搜索可以短暂滞后，但查询必须带 indexedThroughSequence 或等价水位。落后于当前提交时显示更新中，不能把旧数量当最终完成。
- 统一错误至少包括 INVALID_INPUT、NOT_FOUND、DELETED、VERSION_CONFLICT、IDEMPOTENCY_CONFLICT、REFERENCE_UNAVAILABLE、STORAGE_FAILED、CAPACITY_EXCEEDED、SERVICE_UNAVAILABLE、CANCELLED。错误需可恢复说明与受影响字段；底层异常不直接替代产品提示。

## 导航与备份

导航前保留当前对象、版本或编辑草稿、文稿段落锚点、滚动位置、地图视野、时间视图、查询条件。进入引用、地图或讨论后返回，不丢弃当前草稿，不重新打开一份副本。

备份包包含格式版本、工作空间身份、草稿与正式对象、完整修订、引用关系、地点与时间视图、人物资料版本范围、讨论消息与采纳链、预言及其评估、附件清单和摘要校验信息。外链保留地址，不宣称已备份外部网页内容；已导入材料及本地附件应真实打包。

首版恢复支持导入到新的空工作空间，校验通过后整体生效，保留对象 ID 与引用；不覆盖当前工作空间。不承诺把多个已有工作空间智能合并。解析失败、缺附件和版本不兼容必须明确报告，原工作空间保持可用。
