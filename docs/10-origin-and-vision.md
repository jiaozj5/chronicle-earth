# 最初动机与理想使用方式

整理日期：2026-10-03。依据最初的「细化云端众神与地球史书」讨论、后续「设计材料藏书阅读格式」中的用户修正及已有工程规格整理。本文保存产品意图，不把愿景或讨论中的细节当作已实现功能；当前状态见 [实现与后续工作](11-status-and-roadmap.md)。

## 最初想做什么

用户最早把它称作一款“游戏”，并要求只围绕自己的设想讨论，不与已有游戏作联想比较。原始意象是：

> 云端之下，众生林立，真实的地球，岁月的史书，时间地点人物事件构成每一个点，时间是图层，事件绘点缀在地球之上；云端之上，众神林立，过去现在的在各个领域的伟人都在这里。

用户希望能够塑造这些人物，与他们交流，并以他们留存于世的知识为根基。最初讨论关注最终呈现的感受，而非实现技术。

从这一意象中，项目逐渐形成了个人工作空间的目标：方便地留下自己关注的世界，把零散材料组织成自己的理解，通过讨论、推演、修订和回顾让理解继续生长。它同时需要保存人的经历、阅读与思考；“游戏”意味着愿意反复回来探索和停留的体验，没有确立积分、排行榜或任务奖励的需求。

初期讨论曾展开历史场景、人物居所、多人交流等想象。这些是愿景素材；其中的建筑重建、人物动画、全部历史知识等没有转化为当前交付承诺。

## 云下与云上如何相连

**云下：岁月史书。** 同一个地点在不同时代承载不同事件；同一时间也能观察不同地点。时间图层帮助观看自己的记录，地点和地图帮助找回它们。个人经历、关注的历史、尚不确定的材料和面向未来的预言都可以存在，保存时不必先完成考据和分类。

**云上：思想与人物。** 原材料、文稿、概念、观点、问题、论证和资料型人物构成思考空间。抽象思想可以独立存在，不必强行绑定地点。人物讨论需要知道用了哪些材料，原文和模型推演应能辨认。

**联系：带出处地发展理解。** 一条史书记录可以成为观点的例子或反例；一段书中文字可以成为论据；一次讨论可以被用户编辑后采纳。以后回看时，仍能找到当时使用的原文与版本，理解自己为什么改变了想法。

## 已明确的取舍

| 方向 | 当前应保留的含义 |
| --- | --- |
| 用户自己的史书 | 默认不预填世界历史，不自动替用户形成观点或点亮探索 |
| 随手留下内容 | 一句话即可保存，缺时间或地点时也允许待整理 |
| 地图为主体 | 中文浅色地名，按需展开目录和正文，阅读与书写可专注 |
| 图书馆体验 | 书架里的书对应实际藏书，原版阅读、精确批注和沉浸布局服务于阅读 |
| 转换与入库分开 | 转换放在材料藏书内部，检查/下载后再明确选择加入藏书 |
| 外部 Agent 操作 | 自然语言交流在 Codex 或支持工具的客户端进行，应用负责可靠接口和执行反馈 |
| 阅读器保持安静 | 左侧恢复目录与查找，不在阅读器内放 AI 伴读/模型选择窗口 |
| 人物有资料边界 | “全部留世知识”是理想追求；实际只声称使用当前可用、可追溯的资料 |
| 本机优先 | 单人私有工作空间可离线记录、阅读和查找，外部模型失效不阻断核心能力 |

这些取舍中，地图主体、汉字地名、转换并入藏书、取消阅读器内聊天都是用户后续明确提出的修正。桌面本机服务、SQLite、首版不做三维地球等属于工程基线选择；二者应分别理解。

## 理想状态下一次完整使用

以下是目标体验，当前可用入口见根目录 [使用说明](../README.md)，未完成部分见 [路线图](11-status-and-roadmap.md)。

1. **先记录。** 生活中遇到一件事、想到一个问题或看到一段材料，先留下正文。愿意时再补充时间、地点、人物和出处；输入过程不被表单打断。
2. **重新遇见。** 打开某个时间图层或地点，从地图和目录回到旧记录。模糊日期、历史别名和未知信息仍按原意保留，不伪装精确。
3. **带着问题读书。** 进入自己的图书馆，打开一本实际收藏的书。在纸页上选择文字、公式或区域，留下标记和批注；关闭后回来仍能接上阅读位置。
4. **请 Agent 帮忙。** 在外部客户端说“找到本书解释这个观点的段落，带我过去，给这段加下划线并保存我的问题”。Agent 先读操作规范和当前窗口，再查找、定位、执行并回读；含糊时应澄清，不能把待执行命令报成成功。
5. **形成自己的理解。** 从记录和批注里挑出材料，建立概念、观点或连续文稿，写清自己的判断；原文、解释和反例都能沿引用回去。
6. **与人物讨论。** 给一个资料型人物选择明确的材料范围，带着问题交流。人物可以追问和提出不同看法；超出资料的推演有明确身份。是否采纳、如何改写由用户决定。
7. **向未来推演。** 根据当前认识写下条件、依据和预言。过一段时间主动复盘，保留首次判断和后来每次修订，而不是覆盖过去的自己。
8. **长期积累。** 内容更多后仍容易找回，能导出、恢复、迁移；未来换电脑或开发者时，内容的身份、引用和来历不会丢失。

理想效果是能够从具体经历走向思想，又从思想回到具体证据。连续回访和真实阅读比增加视觉噱头更能检验它是否成立。三维世界、人物居所、多人讨论等可以继续讨论，但不能挤掉可靠保存、阅读和引用这条主线。

## 给后续 Agent 的判断标准

评估新功能时，先说明它改善上面哪一步，以及怎样证明改善。不要为了“更像游戏”自动加入任务奖励，也不要为了“更智能”让模型静默替用户改写正文、归属或判断。新的界面可以变化，用户对内容的控制、原始证据和长期可读性需要延续。
